## [Unreleased]

### Added
- `test-map` skill: renders a test file as a map instead of a wall of code — the file's one-line coverage sentence, the shared `beforeEach`/factory state written once with its values resolved, then each test as `given`/`when`/`then` plus the regression it catches, and a `Read first` line naming the two or three tests that hold the primary behaviour. Nothing existing does this: `vitest list`, `playwright test --list`, `mocha --dry-run` and the VS Code and JetBrains test explorers all render the run, so you get a tree of test names and never what a test sets up, calls, or asserts — which is the half that is hard to read. The map comes from the source, not from a run; the collection command is used only for `it.each` and loop-generated names that do not exist in the source, because collection executes module-level code and `describe` bodies and can start a server. Jest is the one framework with no name-level dry run — `--listTests` prints file paths only — so its dynamic names are derived from source and the output says so. Read-only, on demand, and it closes with the failures from the `tests-and-comments` rule: a name that disagrees with its assertion, a test asserting a mock it just configured, two tests differing only in a value, a test with no assertion
- `git/.gitignore_global`: `portless.json` — Portless writes this per-project config on each machine it runs on, so it is ignored globally instead of in every project's own `.gitignore`
- settings: `outputStyle` set to `Concise`, the built-in style that appends "Keep your responses short and direct while doing the work just as thoroughly" to the system prompt. No style was set before, so every session ran the default. This overlaps with the `straight-talk` rule, which already bans preamble and unrequested next steps — keep both: the style text reaches the model as part of the system prompt while the rule arrives as project instructions, and the two are read at different points. The value is case-sensitive and must match the built-in name exactly
- settings: `mcp__plugin_atlassian_atlassian__addCommentToJiraIssue` deny rule — Claude cannot post a Jira comment at all; a comment goes out under your Atlassian account into a shared tracker and cannot be quietly retracted. Deny rather than `ask` because deny is the only form that holds in every permission mode: `ask` forces a prompt in `default` mode but an `auto`-mode session with no matching rule leaves the decision to the classifier. Reading issues is untouched — the server-level `allow` entry still covers `getJiraIssue` and the search tools
- settings: `Bash(rm *)` deny rule — Claude cannot run `rm` at all, and deletes go through `trash` (macOS ships `/usr/bin/trash`), which is recoverable from the Finder trash. Claude Code splits compound commands on `&&`, `||`, `;`, `|`, `|&`, `&`, and newlines and matches each subcommand independently, so one wildcard rule covers `cd client && rm -rf test` and every flag spelling; bare `xargs` is stripped, so `xargs rm -rf` matches too. A `PreToolUse` hook was tried first, with an allowlist that let `rm -rf node_modules` through, and dropped: deny rules are evaluated before `ask` and `allow` and specificity does not reorder them, so no permission rule can carry the exception, but the hook that could had to scan tokens without parsing shell syntax — it denied `rg 'rm -rf' file` within minutes of being installed. Trading `rm -rf node_modules` for a guard with no false positives and no script to maintain
- `answer-dont-act` rule: an explanation question produces an explanation only — no `Edit`, `Write`, or commit on that turn; a real problem found while answering is described in prose and waits for the go-ahead
- `answer-only-gate` hook (`UserPromptSubmit`): detects explanation-shaped prompts and injects the answer-only reminder for that turn. An imperative verb in command position cancels it, so "why is this slow? fix it" is unaffected while "why did you add the retry?" still trips — the verb's clause position is what separates the two
- `explain-pr` skill: explains a pull request in plain English for a reader who does not know the project — a fixed six-section template written in ASD-STE100 Simplified Technical English, plus a worked example; reads file statistics rather than the diff, and reports mismatches between the description and the files changed
- `grill-with-docs` rule: routes "grill me" and plan stress-testing to the mattpocock-skills plugin (`grilling` + `domain-modeling`), so no prefixed slash command is needed; preferred over `grill-me`
- `straight-talk` rule: enforces honest, peer-level communication with no flattery, filler praise, or false validation (always-on)
- `straight-talk` skill: portable version of the rule for sharing with teammates
- `tests-and-comments` rule: every test and comment must earn its place — no narration comments, no external references in source, tests target behavior boundaries and must state what regression they catch
- `no-commit` skill: holds every change in the working tree for manual review — no `git commit` in any spelling, no `git add`, no `gh pr create`; the turn ends when the work does, with no prompt to commit, and only an explicit later instruction releases the hold. Written for the auto-mode path after a plan is approved, where `Bash(git commit:*)` in the `allow` list otherwise lets a commit through with no prompt. It is a reminder, not a guard: the `allow` rule is unchanged, so a deny rule or a `PreToolUse` hook would be what actually blocks the command
- `codebase-memory` skill and settings hooks wiring the codebase-memory MCP server into sessions (PreToolUse gate on Grep/Glob, SessionStart and SubagentStart reminders via `~/.claude/hooks/cbm-*` scripts)
- `write-a-skill` skill: guides creation of new Claude Code skills with proper structure, descriptions, and review checklist

### Changed
- `grill-me` skill: the ADR trigger is now a three-condition gate instead of "an answer that closes a branch with a trade-off, an option rejected for a stated reason". That wording fired on every question by construction — the `❓ Q<n>` format demands labeled options and a falsifiable recommendation, so every answer closes a branch and rejects an option — and it produced 23 ADRs across three repos, 10 of them in fhwpc-platform inside 34 days and 5 landing in one 4-growth commit, averaging 570 words. Most recorded what the code does rather than a constraint the code cannot state: a React deduplication, which of two existing factor sets a select reads, an accessibility deviation whose conformant fix was already scheduled. The grain was wrong, and fhwpc ADR 0005 proves it — written 2026-09-14, superseded by ADR 0007 on 2026-09-15, so it was never hard to reverse. An ADR now needs all three of hard to reverse, not visible in the code it governs, and a rejected alternative a future reader would re-propose; a named list of non-qualifying cases makes the gate checkable rather than self-judged, and a decision that would supersede an ADR written in the same area within the last month amends that file instead of stacking on it. Zero ADRs is stated as the expected number for a session, a paragraph is a complete ADR with `Considered options` and `Consequence` optional, and a settled decision that fails the gate goes in the PR description or commit message — the same destination `rules/tests-and-comments.md` already gives an explanation too long to be a comment. Glossary writes are unchanged, as is the write-as-it-settles cadence, so an interrupted session still leaves a record. The gate is adapted from `grill-with-docs/ADR-FORMAT.md` in `Vizzuality/skills` and inlined rather than referenced, since that skill lives in another repo
- `tests-and-comments` rule: rewrote the Comments half. The old text banned narration — "increment the counter" — which Claude never writes, then permitted "a non-obvious invariant, a deliberate deviation from the expected approach", which is every comment that actually had to be cut. That test is self-assessed at the moment the model has just discovered the fact, so it always passed. Replaced with two conditions a reader can check: the comment names a cause outside the file (an upstream bug, a library default, a platform limit, a data quirk) and it fits on one line. The one-line cap is the strict part and it is deliberate — half the requests were "simplify this comment", not "delete it", and the old rule was binary so a four-line paragraph passed. The overflow route is now an instruction rather than a mention: write the sentence in the PR description, the commit message, or the doc beside the code, in the same change. Also new: no stacking two reasons in one comment, and a check before reporting work finished — state each added comment's outside cause in the response, delete the ones you cannot state. Traced in `fhwpc-platform-client/f7ee76eb`, where the rule sat at transcript line 24 and the comment it failed to stop was written at line 554. No hook yet — a `PostToolUse` matcher on `Edit|Write` that counts added comment lines is the next step if the rule alone still drifts
- `straight-talk` rule and skill: added a "Banned words" section with a named list, replacing a principle that named only three metaphors and was not holding. Each word carries its plain-English replacement in a table, and the rule states that the fact stays when the word goes, so obeying the list never deletes information. A closing line — before you write a word that paints a picture of the code, write what happens instead — covers the synonyms the list misses. `idempotent` is banned with the rest, at the cost of one longer sentence. `gate` is left legal: `answer-only-gate` and `cbm-code-discovery-gate` are hook files here and a SonarQube quality gate is a product feature, so a ban would stop Claude naming your own files — the "a name is not jargon" line makes that general. Also new: no invented acronyms (`initialVerification`, never `IV`), no "You're right" openers, and a self-check before sending. The rule now governs commit messages and PR descriptions, not chat alone. Still no hook — the only event after a reply is `Stop`, whose single power is making the model write more
- `straight-talk` rule and skill: added a "Plain language" section anchored on ASD-STE100 Simplified Technical English, matching `explain-pr` — the standard carries sentence length, active voice, and word choice, and its Technical Names and Technical Verbs rule keeps terms like `useEffect` legal, so the section only names the failures STE does not: abstraction in place of the real file or function, hazard-speak instead of what happens, metaphors for code, answers that continue past the answer, and repeating a message with more words when it did not land
- `straight-talk` rule and skill: put "Plain language" ahead of the honesty rules, since jargon is the more frequent failure and order in an always-on prompt is not neutral; the original bullets keep their wording under a "Honesty" heading, which the reorder made necessary — "Rules" read as a leftover bucket once a second rule list sat above it
- global `CLAUDE.md`: documented the hooks path mapping, which was missing — hook scripts are symlinked into `~/.claude/hooks/` per file, since that directory also holds vendor-installed scripts and cannot itself be a symlink
- settings: enabled `vizz-core` (Vizzuality marketplace), `warp`, and `mattpocock-skills` plugins, registering the vizzuality and claude-code-warp marketplaces
- settings: disabled the Bash sandbox
- settings: moved `defaultMode` into the `permissions` block per current settings schema
- settings: enabled fullscreen TUI and hold-to-talk voice input
- settings: default model changed from `claude-opus-4-6` to `opus[1m]` (Opus 5, 1M context)
- global gitignore: expanded AI-tool entries (CLAUDE.md, CONTEXT.md, AGENTS.md, `.claude/`, `.agents/`, `.mcp.json`, `.playwright-mcp/`, copilot instructions, skills-lock.json)
- `no-commit` skill: added a "Releasing the hold" section naming the words that lift it — `pr`, `commit`, `push`, anywhere in the message — with an instruction to act on them silently: no confirmation, no options, no `AskUserQuestion`, no announcement that the hold is lifted. The old text released only on "an explicit later instruction to commit", which made "create pr" a judgement call, and across 13 sessions it went both ways: seven released it on the spot, four stopped to confirm. `93e74ae1` answered "create a pr" with "I'm not going to assume 'create a pr' lifts it. Confirm and I'll commit" and needed a second message saying "go"; `db8b36c7` reasoned that "'Create a PR' implies a commit rather than stating one"; `b5c1a88f` opened the picker with "Lift the no-commit hold and open a PR into dev?". A genuine blocker — a failing check, an unrelated change in the diff, no obvious base branch — is still raised; the hold itself is not a question any more
- `grill-me` skill: rewritten as the single owner of grilling. It now carries the design tree and frontier traversal taken from `mattpocock-skills:grilling`, the one-question-per-message and no-picker rules taken from the deleted `grill-with-docs` rule, the `docs/domain/` glossary and ADR triggers, and an opening line that invokes `no-commit` — which had been a manual step in 18 of the 26 sessions that later committed. The measured reason for the rewrite: across 36 past grilling sessions, `grill-me/SKILL.md` was loaded in 1 while the rule routed 34 into the plugin, whose "ask the whole frontier in one round" loads at invocation time, after the always-on rule, and beat it every time. Two earlier fixes (`5fec89a`, `266d9d7`) rewrote the override and did not hold — ten messages carried between two and five questions, drawing "one question at the time!", "1 question at a time please" and "wtf, give me 1 question at a time". Position is what fixes it, not wording: nothing in context now says to batch. One line in the skill names the plugin and says not to invoke it, because its description still matches "grill me" on its own. Two rules are new. One *open* question at a time covers stacking a question on an unanswered one, which the old text never named and which happened anyway. And `AskUserQuestion` is banned by name for grilling questions — the old rule banned "any interactive picker" and the picker was still used 20 times, 4 of those batching two questions in one call. The description is written to fire on `/grill-me` as plain text inside a sentence, which is how it is actually typed; only 1 of the 36 sessions was a real expanded slash command
- `grill-me` skill: shortened closed-questions rule for brevity
- `grill-with-docs` rule: added a presentation override so `grilling` asks one closed, labeled question per message instead of batching the whole frontier — the plugin's design-tree traversal with the `grill-me` prompting style
- `grill-with-docs` rule: gave the presentation override its missing rationale and precedence — why the picker is banned (truncated option bodies), why questions are serialised (answers reframe the frontier), that `grilling`'s `❓`/`➡️` format survives with cumulative numbering, that recommendations must state what would change them, and that markdown wins over `AskUserQuestion` in plan mode
- `grill-with-docs` rule: added a domain-model section with concrete triggers and paths (`docs/domain/glossary.md`, `docs/domain/adr/NNN-<slug>.md`), written as each decision settles — previously "maintain the domain model as decisions crystallise" had no trigger, threshold, or destination, so nothing was ever written

### Removed
- `grill-with-docs` rule: deleted. Its first line — "Prefer this over `grill-me`" — is what caused the batching, by routing every grilling session into the plugin skill whose own text says to ask the whole frontier in one round. Grilling now lives entirely in the `grill-me` skill. `mattpocock-skills@claude-plugins-official` stays enabled; only the routing to `grilling` goes, and `tdd`, `code-review`, `diagnosing-bugs` and the rest are untouched
- settings: the reordered keys in this diff (`model`, `outputStyle`, `voiceEnabled`) are Claude Code rewriting the file, not an edit

### Fixed
- settings: the Atlassian permission rules were spelled `mcp__atlassian__<tool>` and matched nothing. Claude Code namespaces MCP servers that come from a plugin as `plugin_<plugin>_<server>`, so the live tool names are `mcp__plugin_atlassian_atlassian__<tool>` — the plugin's own `.mcp.json` names the server `atlassian`, which is what the rules had been copied from. All eight `ask` rules and the server-level `allow` entry were dead: `createJiraIssue`, `editJiraIssue`, `transitionJiraIssue`, `addWorklogToJiraIssue`, `createConfluencePage`, `updateConfluencePage` and `createIssueLink` were relying on the default permission prompt instead of the `ask` rules meant to force one
- `install.sh`: `claude/hooks/` was never linked, so a fresh machine got the hook entries in `settings.json` with no scripts behind them — `answer-only-gate` had been symlinked by hand. Hooks are now linked per file, skipping `*.test`
- global `CLAUDE.md`: the configuration block pointed at `~/Developer/dotfiles`, which does not exist — every path now names the real source, `~/dev/vizzuality/dotfiles`
